# to-review — 리뷰 큐를 한 번에 돌린다

내가 리뷰어인 열린 PR을 모아 **대기 오래된 순으로 보여 주고**, PR마다 서브에이전트를 하나씩 띄워 **`review-pr` 스킬로 리뷰**한 뒤, 결과를 **한 표로 종합**한다. 리뷰 하나하나의 절차와 보고 형식은 `review-pr`이 정하고, 이 스킬은 그것을 여러 PR에 병렬로 돌리고 모으는 일만 한다.

리뷰 큐는 오래 기다린 PR이 위에 오도록 정렬한다. 대기가 길수록 작성자가 막혀 있을 가능성이 크기 때문이다.

## 옵션

| 옵션 | 설명 |
|---|---|
| `--repo <owner/repo>` | 특정 저장소의 PR만 |
| `--limit N` | 대기 오래된 순으로 상위 N건만 리뷰. 나머지는 목록에만 표시 |
| `--list-only` | 리뷰 없이 목록만. 예전 "가벼운 목록 뷰" 동작 |

## 절차

### 1) 큐 조회

`${CLAUDE_SKILL_DIR}/scripts/fetch-review-queue.sh` 를 실행한다. `--repo` 가 있으면 `${CLAUDE_SKILL_DIR}/scripts/fetch-review-queue.sh --repo <owner/repo>` 로 넘긴다. (권한 자동 승인을 받으려면 이 경로 그대로, `bash` 프리픽스나 파이프 없이 실행한다.)

스크립트가 `gh`·`jq` 존재 확인, 로그인 1회 조회, PR별 메타데이터 병렬 조회, 정렬까지 모두 끝내고 아래 JSON 하나를 준다. 추가로 `gh` 를 직접 조합할 필요가 없다.

```json
{"me": "login", "total": 15, "prs": [{"repo", "number", "title", "author", "body", "url", "isDraft",
  "baseRefName", "headRefName", "changedFiles", "additions", "deletions",
  "elapsed": "8일 21시간", "elapsedHours": 213, "elapsedSource": "review_requested" | "created"}]}
```

`prs` 는 이미 `elapsedHours` 내림차순이다. `elapsedSource` 가 `created` 면 개인 리뷰 요청 이벤트를 못 찾아 PR 생성 시각으로 잰 근사치다.

`total` 이 0이면 `리뷰 대기 중인 PR이 없습니다. 🎉` 한 줄만 출력하고 끝낸다.

### 2) 목록 먼저 보여 주기

리뷰는 PR당 수 분이 걸린다. 사용자가 그동안 큐 전체를 파악할 수 있도록 목록을 먼저 출력한다.

```markdown
## 📋 리뷰 대기 PR — {N}건 · 대기 오래된 순

| # | PR | 대기 | 변경 | 제목 |
|---|---|---|---|---|
| 1 | [{repo}#{number}]({url}) | {🔴/🟠/🟢} {elapsed} | {changedFiles} files · +{additions}/−{deletions} | {[Draft] }{제목에서 티켓 접두사를 뺀 것} |
```

- `{repo}` 는 `nameWithOwner` 의 뒷부분만. `−` 는 U+2212.
- 긴급도: `elapsedHours ≥ 72` 🔴, `≥ 24` 🟠, 그 미만 🟢. `elapsedSource == "created"` 면 `elapsed` 뒤에 `~` 를 붙인다.
- `--limit N` 이면 N+1번째부터는 `(목록만)` 을 제목 끝에 붙인다.

`--list-only` 면 여기서 끝낸다. 이때는 제목 대신 **본문을 읽어 만든 한 줄 요약**을 쓴다. 제목이 티켓 번호뿐이어도 열어 보지 않고 감을 잡게 하는 것이 목록 뷰의 가치다. 본문이 비었으면 제목을 정제해 쓰고, 지어내지 않는다. 마지막 줄에 "목록만 조회했습니다. 리뷰하려면 `--list-only` 없이 다시 실행해 주세요." 를 적는다.

### 3) PR마다 서브에이전트로 review-pr 실행

리뷰 대상(`--limit` 적용 후) 각각에 대해 **서브에이전트를 하나씩, 한 메시지에서 동시에** 띄운다. 8건을 넘으면 6~8건씩 나눠 띄우고 앞 묶음이 끝나는 대로 다음을 띄운다. 한 번에 너무 많이 띄우면 같은 저장소에 대한 `git fetch` 가 몰려 느려진다.

각 에이전트에게는 아래 틀을 그대로 채워 넘긴다. 에이전트는 이 세션을 볼 수 없으므로 필요한 것을 전부 프롬프트에 담는다.

````
다음 PR을 리뷰하라.
- 스킬: {CLAUDE_SKILL_DIR의 부모}/review-pr/SKILL.md 를 먼저 읽고 그대로 따른다. 그 파일의 ${CLAUDE_SKILL_DIR} 는 {CLAUDE_SKILL_DIR의 부모}/review-pr 를 뜻한다.
- 대상: {owner/repo} PR #{number} ({url})
- 로컬 저장소: {아래 "로컬 저장소 찾기" 결과. 없으면 "없음 — diff만으로 진행하고 보고서에 호출부 미확인을 명시"}
- 워크트리를 만들 때는 {스크래치 디렉터리}/{레포명}-pr-{number} 를 쓴다. 다른 PR과 섞이지 않게 하기 위해서다.
- 결과: review-pr 의 보고서 형식 그대로, 최종 메시지로 돌려준다. 파일로 저장하지 않는다. 보고서 앞뒤에 인사말·작업 메모·요약을 붙이지 않는다. 종합할 때 보고서만 그대로 싣기 때문이다.
- 제약: GitHub에 아무것도 쓰지 않는다 (gh pr comment / gh pr review / gh api 의 쓰기 호출 금지). 로컬 저장소 파일을 수정하지 않는다.
````

에이전트에 이름을 붙이는 것은 선택이다. 환경에 따라 이름 지정이 거부되면 이름 없이 다시 띄운다.

**로컬 저장소 찾기.** `review-pr` 의 4)단계(호출부 추적)는 코드가 로컬에 있어야 제대로 된다. 다음 순서로 찾아 경로를 넘긴다.

1. 현재 디렉터리의 `git remote get-url origin` 이 그 PR의 저장소면 현재 디렉터리.
2. 아니면 현재 디렉터리의 부모 아래에 레포명과 같은 이름의 git 저장소가 있으면 그것. (한 폴더에 저장소를 모아 두는 흔한 배치를 위한 것이다.)
3. 둘 다 아니면 "없음".

에이전트가 돌아오면 보고서 첫 세 줄(**목적**, **목적 대비 구현**, **결론**)에서 결론과 이슈 건수를 읽어 둔다.

에이전트가 끝났다는 알림은 왔는데 보고서 본문이 함께 오지 않으면(전달 실패, 빈 결과), 그 에이전트에게 메시지로 "보고서 전문을 다시 보내 달라"고 요청해 받는다. 그래도 못 받으면 4)의 실패 처리로 넘긴다. 리뷰를 다시 돌리지는 않는다. 비용이 크고 결과는 이미 있기 때문이다.

### 4) 종합 출력

모든 에이전트가 끝나면 아래 순서로 출력한다. 요약 표가 먼저 와야 사용자가 어디부터 볼지 정할 수 있다.

```markdown
## ✅ 리뷰 결과 — {리뷰한 건수}건

| # | PR | 대기 | 결론 | 이슈 | 가장 심각한 것 |
|---|---|---|---|---|---|
| 1 | [{repo}#{number}]({url}) | {elapsed} | {머지 가능 / 수정 후 머지 / 재검토 필요} | P0 {a} · P1 {b} · P2 {c} · P3 {d} | {최고 심각도 이슈의 제목 한 줄, 없으면 —} |

---

{1번 PR 보고서 전문 — 보고서 자체의 "## PR #… 리뷰 — …" 제목이 곧 절 제목이다}

---

{2번 PR 보고서 전문}
```

- 순서는 2)의 목록과 같다 (대기 오래된 순). 순번은 요약 표에만 둔다. 보고서 위에 제목을 또 달면 같은 제목이 두 번 나온다.
- 보고서 전문의 범위는 `## PR #… 리뷰 —` 제목 줄부터 "GitHub에는 아무것도 남기지 않았습니다…" 줄 **직전**까지다. 그 범위는 **고치지 않고 그대로** 싣고, 그 밖의 것(에이전트의 인사말, 작업 메모, 워크트리 정리 보고)은 뺀다. "GitHub에는…" 줄은 PR마다 반복되므로 맨 아래 한 번만 적는다.
- 에이전트가 실패했거나 형식에 맞지 않는 결과를 돌려주면 그 PR 행의 결론에 `실패 — {이유 한 줄}` 을 적고 전문 자리에 에이전트의 마지막 메시지를 그대로 둔다. 조용히 빼지 않는다.
- `--limit` 으로 리뷰하지 않은 건이 있으면 표 아래에 `_(+M건은 --limit로 목록만 표시)_` 를 적는다.

맨 아래 한 줄: *"GitHub에는 아무것도 남기지 않았습니다. 특정 PR에 코멘트로 올리려면 PR 번호와 함께 말씀해 주세요."*

## 원칙

- **쓰지 않는다.** 이 스킬도, 띄운 에이전트도 GitHub에 코멘트·리뷰·approve를 남기지 않는다. 사용자가 PR을 지목해 명시적으로 요청하면 그때 `review-pr` 의 7)단계 절차를 따른다.
- **리뷰 내용은 review-pr 의 것이다.** 이 스킬은 에이전트가 돌려준 보고서를 요약 표로 묶을 뿐, 결론이나 심각도를 고쳐 쓰지 않는다. 표의 결론과 전문의 결론이 다르면 사용자가 신뢰할 수 없다.
- **목록을 먼저.** 리뷰가 끝나기를 기다리게 하지 말고 큐 전체를 먼저 보여 준다.

## 스크립트

| 스크립트 | 용도 |
|---|---|
| `scripts/fetch-review-queue.sh [--repo owner/repo]` | 큐 전체를 메타데이터 포함 JSON 하나로. 이 스킬이 호출하는 유일한 스크립트 |
| `scripts/fetch-pr-meta.sh <owner/repo> <번호> [login]` | PR 하나의 대기 시간·변경 규모. 위 스크립트가 내부에서 병렬 호출 |
